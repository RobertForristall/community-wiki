# MVP Testing

Following the development and internal testing of the project's MVP, it is time to open the project up to a dedicated testing phase where test users can be selected to interact with the MVP and provide feedback on the project. The feedback from these users will be crucial in determining if the project has reached a viable MVP state or if there are noticable issues that need to be handled. This time can also be used to get metric based data about the project to present to concerning bodies in order to ensure that all requirements of the project are being met to the standard that was outlined for it.

## Test User Selection

One of the hardest parts of this phase of the project lifecycle is finding enough quality test users for the MVP of the project. These users should have an interest in the project as both a potential future user or someone that works/interacts with someone that would be a potential user. It is also important to find some test users with knowledge of development practices that may be better suited at testing the robustness and reliability of the project by attempting to break it in ways that tech savy individuals are able to consider.

### Key Qualities:
1. Some users that will be future users
2. Some users that know how to break software
3. Some users from concerning bodies for direct feedback

### Where To Find Users
1. Contacting concerning bodies
2. Social media sites
3. Followers of the project
4. Friends/Associates of current project memebers

## Test Enviornment

While performing the test user selection it is also important to prepare a dedicated testing enviornment for these test users to interact with. In most cases it is best practice to make the testing enviornment as close to what it will be like in production to ensure that the project is being tested in the most accurate state it can be. With a testing enviornment make sure to include a guide for the testing users that should tell them what features or aspects of the MVP that you are most concerned with them interacting with as these features may differ based on the background of the individual participating in the test.

## Test User Feedback

Each user should have a simple manner of providing feedback to the team about their experience using the project's MVP. In most situations something like a prepared form that lists out key features that the test user should have interacted with and dedicated space for feedback about that feature are more than enough for user feedback. Additional forms of feedback could include direct communication with highly important test users and additional development operations metrics to easily visualize/quantify the performance of different aspects of the project. All of this feedback should be gathered and analyzed in order to determine if the project is ready to be released as a viable MVP or if additional work needs to be done.
