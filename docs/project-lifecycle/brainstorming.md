# Brainstorming

The first stage of any project is brainstorming what the project will be. In general terms this means finding answers to the following questions:

## 1. What does the project do

What does the project do at the high level and how does it achieve this goal. This does not need to be too indepth since at this stage in the process there are still many aspects of the project that will need to be discussed and determined. At the very least each member of the project should be able to give a brief summary of what the project does and what will need to be done in order to develop a MVP.

## 2. What problems does the project solve

This is one of the most important questions to ask when brainstorming since a good problem to solve will lead to a project that will actually be used by users. In addition to identifying the problems that the project solves it is important for everyone to understand why solving these problems is worthwhile since it will allow for a better proposal of the project's worth to outside influences along with providing a good motivation to members of the project that their work will be rewarded in some way.

## 3. How will users interact with the project

Similar to what the project does, it is important to understand how different users will interact with the project. If the project has a UI what is the high level workflow of a user's interaction going to be like or if the project is a backend based service how will users consume data from the service or request it to perform some kind of work/action. This level of understand will be key in developing a project that is usable by the dedicated target audience while also aiding in future design methods that can be employed for the project.

## 4. How does the project compare to others in the market

For a project to truly succeed it should be used somewhere by someone, for this reason it is important to compare the ideas of the project against others that are similar which already exist in the market. To learn where others succeeded or failed is crucial for designing a useful project and being able to promote that project to perspective users since there will be competition for getting your project seen and adopted.
