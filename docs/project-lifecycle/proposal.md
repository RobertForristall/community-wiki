# Proposal

With a solid understanding of the high level aspects of a project, it is time to begin working on a dedicated proposal that can be demonstrated to others whether they be investors, potential contributors, etc. During this process there will likely be multiple iterations of the proposal until it is accepted by any moderating parties to ensure that a clear goal and vision for the project is established that will lead to its success. To aid with this there are a number of tools/philosophies that can be adopted and prepared.

## Design Document

Likely the most important thing that can be made at this stage of the project lifecycle is a dedicated design document that outlines a number of different aspects of the project in a clear and concise manner:

1. Executive Summary: This section outlines a very high level description of the project, its objectives, and approach that will be taken in order for the project to succeed.
2. Narrative Description: This section outlines why the project is worthwhile from a user's perspective such as outlining the problems it solves and how
3. Goals/Objectives: A detailed bulleted list of objectives that the project should be aiming to accomplish with the project at a mid to high level
4. Legal, Ethical, and Privacy Issues: Any concerns that need to be addressed for the project's success that falls within one of these categories
5. Requirements: Technical requirements of the project split across the different tech stack components in order to outline MVP requirements along with additional requirements that would be either nice to have or good for future enhancements to the MVP
6. Technologies: Any technologies that will be used either in the development or functionality of the project in order to make sure all parties involved know what tools are being used
7. Desgin Summary: A clear design summary for how the project will function at a detailed and integrated level across the different tech stack components
8. Development Guidelines: Any guides for how to handle the development process such as contribution requirements and formatting of code
9. Project Milestones: A general roadmap for the development of the project in order to provide an expected date for things like the MVP while also monitoring the overall health of the project during development

While design documents for different types of projects may need additional sections or even not use one of the previously discussed sections, this format for the design document should address most of the concerns that are needed for such a piece of documentation. It is also important to remember that this document is a living document that will never be fully finalized and will have revisions made to it as the development of the project is underway.
