# MVP Development

With all of the designs completed it is time to develop the initial MVP of the project. For clarification, an MVP stands for the Minimal Viable Product of the project. This is a completed software implementation that meets the minimum requirements for the project to be considered a success and always should be prioritized over additional features that may not be necessary to the minimum required functionality of the project.

During this stage of the project lifecycle it is important to follow the outlines created during the design phase of the project in order to minimize additional work from having to be done that does not meet the desired specifications of earlier design documents.

It is also possible that during this phase of development additional criteria or issues could be identified which need to be addressed and may result in revisions being made to the exisiting design documents/methods already started in previous stages.

## Standups

While development of the MVP is going on it will be important to schedule stand up meetings with all active members of the project in order to determine the overall health of development and to determine if any issues may have arrised that need to be addressed. These meetings also work as good oppurtunities to discuss plans for the next set of tasks that will be assigned for the MVP development. Please note that good development practices encourage that a healthy amount of documentation be made during these meetings in order to reflect on success and struggles at the end of the project.

A simple guideline of how to run a standup is as follows:

1. Welcome everyone to the standup with any general news regarding the project that took place
2. Allow each active member a chance to disscuss what they worked on for the week
3. Allow each team lead time to discuss any code revisions that need to be made for open PRs
4. Go over any issues/concerns that have arisen over the previous week
5. Ensure that all members are assigned tasks for the following week

## Updates

Another important aspect that should be handled during the MVP development is regular updates about the project to any concerning bodies that are interested in the project's success. These concerning bodies can include investors, sponsors, potential contributors, potential consumers/users, etc. Without clear updates being given regularly about a project, there can arise concern about the project's health and the competency of the developing team to complete the project within whatever time frame is planned along with meeting the desired state of the project.

Updates to concerning bodies should include the following:

1. A reasurance to all interested parties that development is continuing
2. What advancements in the project have been completed
3. Any noteworthy issues that have been encountered and how they will be addressed
4. Plans for next steps of the project's development
